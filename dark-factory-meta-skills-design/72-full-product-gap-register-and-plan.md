## Product Build Plan

### PB-01: Product Platform Spine

Build a real app shell with project/workspace model, durable database, run ledger, evidence store, user roles, decision queue, comments, and audit log.

Acceptance:

- A user can create multiple projects.
- Runs persist after restart without JSON-file fragility.
- Every action has actor, time, scope, token budget, and evidence link.
- Playwright proves project start, resume, and change-control journeys.

### PB-02: Agent Protocol Runtime

Move from protocol descriptors to working provider orchestration and host-level protocol integration.

Acceptance:

- AG-UI events stream live.
- A2UI surfaces are rendered from safe structured descriptors.
- MCP Apps tools are callable and auditable.
- Provider quorum has request, response, merge, critique, token SWAG, and approval records.

### PB-03: No-Skip Execution Kernel

Make the strict ledger the only way work advances.

Acceptance:

- Every stage has a graph node, ledger bead, inputs, outputs, gate, owner, and downstream closure.
- Future stage calls fail at runtime.
- Reopened nodes rerun transitive closure.
- Hawkeye can veto any stage.

### PB-04: Product-Grade Human-Agent UX

Redesign around the owner journey, not document browsing.

Acceptance:

- First viewport answers mission, current stage, next legal action, blocker, proof class, budget, and human decision.
- UI supports start, interrogate, baseline approval, plan, artifacts, build, test, review, release, audit, redo.
- Desktop and mobile Playwright screenshots show clean hierarchy, no random panels, no blank views, and no text overflow.
- Material 3 design principles are applied with a coherent product system.

### PB-05: Public Reproducibility And CI

Package the repo so a fresh user can clone and validate without private workspace assumptions.

Acceptance:

- GitHub Actions or equivalent CI runs critical tests.
- README install steps match CI.
- Windows long-path risk is eliminated or automated.
- Public repo release excludes local noise and secrets.

### PB-06: Enterprise Operations Layer

Add the service-management layer required to replace a human outsourcing firm.

Acceptance:

- SRE handoff, outage drill, operator signoff, support workflow, incident replay, and training evidence are product features, not only documents.
- Release/change advisory workflow supports approval, rollback, and residual-risk acceptance.
