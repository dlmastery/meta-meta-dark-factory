## Loop Execution Policy

Each loop must produce one of these outcomes:

- `accepted`: concrete evidence exists and no P0/P1 remains for that loop.
- `accepted_with_boundary`: evidence exists, but the loop explicitly records residual risk.
- `partial`: some evidence exists, but important work remains.
- `blocked`: work cannot proceed without a dependency or human decision.
- `planned`: loop is scheduled but not executed.

A loop that only says "reviewed, no issue" without evidence is invalid.
