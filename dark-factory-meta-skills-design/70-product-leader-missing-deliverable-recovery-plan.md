## Executive Truth

The work so far did not solve the owner's real problem.

It produced useful pieces: governance skills, artifact catalogs, validators, a local console, partial AG-UI/A2UI/MCP-style surfaces, truth inventory, no-skip legal-state checks, interrogation gates, artifact BOM generation, and expert-review assignment scaffolding. Those are necessary ingredients.

But the owner's ask is not "generate impressive process documents" and not "make a dashboard." The ask is a working agentic SDLC factory product that can replace the confidence normally bought from a serious software outsourcing firm, with token-budget checkpoints instead of dollar-budget checkpoints, and with stronger artifact, review, implementation, testing, handoff, and audit rigor than a human-heavy consulting process.

The missing deliverable is therefore:

> A working Software Assured Dark Factory Studio: a human-supervised, agentic, no-skip SDLC factory that starts from raw client intent, interrogates and validates requirements, compiles a product-tailored factory, generates and reviews all required artifacts, builds the actual software, proves it with tests and browser/WYSIWYG evidence, lets humans approve/resteer/reopen any node, and maintains a graph/ledger/certificate trail that exposes what is real, what is partial, what is missing, and what must happen next.

The todo/habits app is only a proving ground. It is not the ultimate target.

## What The Owner Actually Wants

### 1. A Meta-Meta Factory

The meta-meta layer must not directly build a todo app. It must generate the right project factory for any serious greenfield or brownfield product.

It must:

- Parse raw, messy, ambitious human intent.
- Separate durable factory requirements from example-project details.
- Choose standards and methods by project type, not by habit.
- Decide full saturation versus tailored-with-waivers.
- Create a Product Tailoring Profile.
- Create a Generated Meta-Skill Contract.
- Create the control graph, work ledger, knowledge graph, PERT plan, task beads, and legal next-action state.
- Require token SWAG and approval checkpoints.
- Install strict anti-skip and anti-template-as-proof rules.
- Require Hawkeye conformance at every stage.

### 2. A Generated Product Meta-Skill

For each actual product, the meta-meta factory must instantiate a product-specific factory.

For the todo/habits example, that product meta-skill must know:

- Product archetype: personal productivity, habit formation, task planning, calendar/time, offline-first or web-app choices.
- User archetypes and behavioral psychology risks.
- UX quality bar and Material 3 design obligations.
- Data model, privacy, sync, reminders, notifications, accessibility, export, and cross-device concerns.
- Required artifacts, templates, rubrics, expert roles, and tests.
- Project-specific no-skip workflow.
- Project-specific expert and adversarial critic panels.
- Project-specific code/test/release gates.

### 3. Product Execution Skills

The generated product meta-skill must then execute real work, not only describe it.

It must produce:

- Interrogation rounds and answer records.
- Recursive spec decomposition.
- Approved baseline and change-control state.
- PRD, SRS, NFR, UX, architecture, security, data, test, release, and operations artifacts.
- Source code.
- Unit, integration, scenario, holdout, transfer, security, accessibility, and browser/WYSIWYG tests.
- Screenshots, logs, trace links, and evidence records.
- Expert reviews, adversarial attacks, fix evidence, and certificates.
- Human handoff and SRE/maintenance docs.

### 4. A Human-Agent Workflow Product

The human must feel they are managing a serious delivery firm, not browsing random generated pages.

The UX must support:

- Start a greenfield or brownfield project.
- See the active mission and current legal next action.
- Answer interrogation questions.
- Approve or reject baselines.
- Watch agent/provider quorum output arrive.
- Inspect the merged proposal.
- See which artifacts/code/tests are required.
- Pause, ask questions, resteer, open change requests, and approve token budget changes.
- Select any artifact or graph node and see downstream impact.
- Reopen a node and rerun its transitive closure.
- Distinguish generated templates from real proof.
- Review evidence, test screenshots, risks, and certificates.
- Resume after context loss without relying on chat memory.

### 5. A Proving Example

The todo/habits app must prove the system works end to end.

The proof must include:

- Real product research and competitive synthesis.
- Validated requirements.
- High-quality app UX using current Material design principles.
- Working app code.
- Complete or explicitly waived artifact catalog.
- Test evidence across real user scenarios.
- Browser/WYSIWYG validation.
- Accessibility checks.
- Security/privacy checks.
- Human portal and redo graph.
- Hawkeye audit.
- Honest residual-risk record.

## Missing Deliverable Product Plan

Product name for planning: Software Assured Dark Factory Studio.

Product promise:

> Start with messy human intent. End with a tested product and a full evidence-backed project book. At every step, the human can see what is real, what is draft, what is blocked, what changed, what it costs in tokens, and what must happen next.

### Layer A: Meta-Meta Factory Compiler

Purpose: Generate the correct factory for a project category.

Required capabilities:

- Intake raw intent and transcript.
- Detect project type: greenfield, brownfield, modernization, migration, compliance, audit, competitor analysis, artifact-only, code-producing, UI-producing, production-facing.
- Create Product Tailoring Profile.
- Create Generated Meta-Skill Contract.
- Select method blend: ISO 12207/15289, SWEBOK, RUP, MDA, DDD, TDD, BDD, Agile, SRE, SSDF, OWASP as applicable.
- Create stage coverage matrix.
- Create artifact generation mode.
- Create token SWAG and reapproval rules.
- Create expert role map and critic panels.
- Create legal next-action graph and no-skip rules.

Exit gate:

- Generated factory contract is project-specific.
- Hawkeye confirms it is not generic.
- Execution kernel names the next legal action.

### Layer B: Generated Product Factory

Purpose: Convert product-specific factory contract into executable skills and project flow.

Required capabilities:

- Create project-specific interrogation protocol.
- Create project-specific artifact BOM.
- Create project-specific expert and critic roster.
- Create implementation plan.
- Create test strategy and scenario matrix.
- Create UX quality rubric and browser validation plan.
- Create code repository target.
- Create release and operations plan when production-facing.
- Create human steering and change-control surfaces.

Exit gate:

- No artifact/code/test stage can start before approved predecessor evidence exists.
- Human approval is required for baseline, budget expansion, scope expansion, production, legal/security/privacy decisions, and waiver acceptance.

### Layer C: Execution Factory

Purpose: Actually perform the project.

Required capabilities:

- Execute customer interrogation.
- Generate artifacts.
- Generate or modify code.
- Run tests.
- Capture evidence.
- Review artifacts/code/tests.
- Patch failures.
- Rerun impacted transitive closure.
- Produce handoff package.

Exit gate:

- Code-producing claims require implementation evidence.
- UI claims require browser/WYSIWYG screenshots and interaction checks.
- Scenario-driven claims require scenario, negative, edge, holdout, and transfer evidence.
- Artifact claims require instantiated artifacts, not templates.
- Review claims require scorecards, critic attacks, fix evidence, and residual-risk decisions.

### Layer D: Human-Agent Studio UX

Purpose: Make the factory understandable and steerable by a human.

First viewport contract:

- Mission composer: what project or change is being run.
- Scenario/template selector: what shape of work this is.
- Active legal next action: exactly what can happen now.
- Human decision card: what needs approval or input.
- Agent quorum preview: who is working and what drafts exist.
- Evidence pulse: what proof exists and what is missing.
- Graph impact inspector: what changes downstream if the human resteers.
- Token budget posture: current SWAG, spent/remaining estimate, reapproval trigger.

Navigation model:

- Start
- Interrogate
- Baseline
- Plan
- Artifacts
- Build
- Test
- Review
- Release/Handoff
- Audit
- Redo/Change Control

UX rejection rule:

- If the screen cannot answer current mission, legal next action, blocker, owner, evidence, draft-versus-proof status, and human decision needed, it fails.
