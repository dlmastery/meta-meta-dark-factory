# Artifact Tailoring

## Non-Negotiable Default

Do not infer a smaller artifact set from project size, local-static implementation, token pressure, or agent convenience. For serious, outsourcing-grade, standards-based, "world's best", "full", certification, "all artifacts", or missed-artifact recovery work, the default mode is `full_saturation`.

Tailoring is allowed only as an explicit human-approved change-control decision. It must name the owner, rationale, scope, token tradeoff, expiry or revalidation trigger, residual risk, Hawkeye reviewer, and exact catalog IDs affected.

The Artifact Catalog Coverage Matrix must enumerate every catalog ID before work proceeds and before closure. In `full_saturation`, every catalog artifact must be generated as a standalone artifact unless an explicit not-applicable justification artifact is approved. `combined`, `partial`, `missing`, and silently `deferred` entries block closure.

Always include:
- Requirements or change intent.
- Acceptance criteria.
- Decisions for material choices.
- Traceability.
- Verification evidence.
- Handoff notes.

Add heavier artifacts when:
- The system is regulated.
- The work crosses teams or vendors.
- Production ownership changes.
- The architecture is novel or risky.
- The codebase is brownfield and poorly documented.
- Security, privacy, reliability, money, or safety risk is high.

Combine artifacts when the project is small, but preserve all required information and links.
